## 一、什么是前端工程化？

**定义：**  
前端工程化是指通过工具、规范和自动化手段，使前端开发更加高效、可维护、可协作。

**本质目标：**  
> 提高效率、保证质量、提升可维护性。

**核心方向包括：**
- 构建与打包（Webpack / Vite / Rollup）
- 模块化与依赖管理
- 代码规范与自动化流程
- 性能优化与部署策略
- 测试与监控体系

## 二、构建工具相关（Webpack / Vite）

### 🧩 1. Webpack 构建流程

1. 读取配置，创建 Compiler 实例  
2. 从入口（entry）出发构建依赖图  
3. 使用 Loader 转译文件  
4. 使用 Plugin 扩展生命周期  
5. 输出 Bundle 文件

**常考点：**
- Loader：文件转换器（处理源码）
- Plugin：功能扩展器（基于事件钩子机制）
- Tree-Shaking、Code-Split、缓存策略等优化点

---

### ⚙️ 2. Webpack 性能优化点

| 优化方向 | 常见手段 |
|-----------|-----------|
| 构建速度 | cache-loader、thread-loader、多进程构建 |
| 打包体积 | Tree Shaking、压缩（TerserPlugin） |
| 首屏加载 | 代码分割、懒加载、Preload / Prefetch |
| 生产优化 | mode=production、去除 console / debugger |
| 可视化分析 | webpack-bundle-analyzer |

---

### ⚡ 3. Vite 原理与优势

**问题：为什么 Vite 比 Webpack 快？**

**回答思路：**
1. 开发阶段基于浏览器原生 ESM，不需打包整站。  
2. 使用 Go 编写的 esbuild 做依赖预构建。  
3. 精准 HMR（热更新）基于模块依赖图。  
4. 构建阶段交给 Rollup 进行 Tree-Shaking 打包。

**加分回答：**
> “Vite 在开发阶段以 `ESM + esbuild` 实现毫秒级热更新，生产环境使用 Rollup 提供成熟的打包优化能力。”

## 三、规范化与自动化流程

### 🧭 1. 代码规范工具

| 工具 | 功能 | 说明 |
|------|------|------|
| ESLint | 静态语法检查 | 结合 `@typescript-eslint` |
| Prettier | 代码格式化 | 与 ESLint 集成需避免冲突 |
| Commitlint | 提交信息规范 | 遵守 `feat/fix/docs/...` 规则 |
| Husky | Git 钩子 | 提交前执行检查 |
| lint-staged | 针对改动文件执行 Lint | 提升性能 |

**高频问法：**  
> “你们团队如何保证代码规范一致？”

**参考回答：**  
> “我们通过 ESLint + Prettier 保证语法与格式统一，Husky + lint-staged 阻止不合规提交，配合 CI 做二次检查。”

---

### 🤖 2. CI/CD 自动化流程

**常考点：**
- 构建流程：拉取代码 → 安装依赖 → 运行测试 → 构建 → 部署
- 工具：GitHub Actions、GitLab CI、Jenkins
- 环境区分：`.env.dev` / `.env.prod`
- 自动版本与日志：`semantic-release`

**面试加分回答：**
> “我们用 GitHub Actions 实现 CI/CD，全流程自动构建与部署测试环境。  
> 每次 push 自动运行 lint + test，构建成功后自动发布。”

## 四、依赖与模块管理

### 📦 1. 包管理工具对比

| 工具 | 特点 |
|------|------|
| npm | 默认、兼容性好 |
| yarn | 并行安装、更快 |
| pnpm | 硬链接机制、节省磁盘、适合 monorepo |

**面试追问：**
> “pnpm 为什么比 npm 快？”

✅ 因为 pnpm 使用符号链接共享依赖，避免重复安装。

---

### 🏗️ 2. Monorepo 管理

**常见工具：**
- pnpm workspace
- Turborepo
- Nx

**常考问题：**
> “如何解决 monorepo 依赖版本冲突？”

**答题思路：**
- 统一依赖版本管理（根目录 `package.json`）
- 使用 workspace 协议（`workspace:^1.0.0`）
- 构建缓存（Turborepo incremental build）

## 五、性能优化与监控

### 🚀 1. 构建性能优化

- 按需加载、动态 import
- 资源缓存（hash 命名 + CDN 缓存）
- 打包分析（webpack-bundle-analyzer）
- 图片压缩（image-webpack-loader）

### 📊 2. 前端监控体系

| 类型 | 实现方式 |
|------|-----------|
| 性能监控 | Performance API（LCP、FCP、CLS） |
| 错误监控 | window.onerror / Sentry |
| 日志上报 | 自定义埋点 + beacon |
| SourceMap 管理 | 生产环境隐藏或上传私有服务器 |

## 六、测试与质量保障

| 测试类型 | 工具 | 场景 |
|-----------|-------|-------|
| 单元测试 | Jest / Vitest | 逻辑函数测试 |

| Mock 数据 | Mock.js / MSW | 模拟后端接口 |

**高频问法：**
> “前端项目中如何保障代码质量？”

**参考回答：**
> “我们集成了单元测试和 E2E 测试，在 CI 中自动执行。  
> 提交前会执行 Lint + Test，测试覆盖率低于阈值无法合并。”
